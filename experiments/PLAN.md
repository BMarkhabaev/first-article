## Методы

### Baselines
- B0: исходная модель.
- B1: удаление первых k блоков (identity) — нижняя граница.

### Методы из литературы (адаптированы к каузальному декодеру, post-hoc)
- L1: фиксированное разреженное внимание — окно w + attention sink (Sparse Transformer [17], BigBird без случайных рёбер [19]).
- L2: strided-шаблон Sparse Transformer [17] (локальное окно + каждый s-й токен).
- L3: Performer FAVOR+ [14] — **стохастический** контроль, несколько seed'ов, среднее ± std.
- L4: линейное внимание elu+1 [11] — без обучения и с дистилляцией.
- L5: Synthesizer-подобное фиксированное внимание [21]: веса зависят только от относительной позиции, оценены усреднением по калибровке.
- L6: A3-подобное аналитическое снижение ранга QK/OV/MLP [22] (их код, если запускается на Qwen3; иначе своя реализация — честно назвать «A3-style»).
- Неприменимы к каузальному LM без переобучения (обосновать в тексте): Linformer [12], Nyströmformer [13] (ориентиры по всей последовательности → утечка будущего), FNet [20] (DFT по всей последовательности), SOFT [16], Reformer [18].

### Наши методы (детерминированные, замкнутая форма)
- O1: **типизированная замена голов** — головы первых слоёв классифицируются по профилю (sink / предыдущий токен / локальная / контентная); позиционные заменяются фиксированным ядром, контентные остаются точными или получают низкий ранг.
- O2: **ridge-свёртка вместо внимания** — подслой внимания блока заменяется каузальной линейной свёрткой по остаточному потоку окна w, коэффициенты — ridge-регрессия на калибровке; MLP точный.
- O3: **аддитивная n-граммная таблица** — выход первых k блоков ≈ e(x_t) + A[x_t] + B[x_{t-1}] + C[x_{t-2}] (+ позиционный член), backfitting/least squares; редкие токены — fallback на среднее.
- O4: **ядро × значимость ключевого токена** — a_tj ∝ K_h(t−j)·exp(β_h(x_j)), таблица β подгоняется
  согласованием масс внимания (IPF), q·k не считается; часть голов можно оставить точными
  (реализовано, см. журнал).

### Аппроксимация MLP (добавлено 2026-11-06 по просьбе пользователя)

Цель: заменять не только внимание, но и SwiGLU-MLP первых слоёв (down(silu(gate·x) ⊙ up·x)),
а затем блок целиком (внимание + MLP). Те же правила: замкнутая форма на калибровке, без SGD;
дистилляция — только в отдельном треке. Позицию 0 считаем точно (массивная активация).

Из литературы:
- M-L1: **A3 FFN** [22] — отбор r нейронов по sqrt(E z_i²)·‖w_down,i‖ (уже реализовано как часть
  L6, выделить в отдельный метод `a3_mlp`, ratio ∈ {0.75, 0.5, 0.25}).
- M-L2: **MLP как память «ключ–значение»** [3] — детерминированная разреженность активаций:
  на каждом токене оставляем top-k нейронов по |z_i| (k фиксировано или порог по калибровке).
  Экономит down-проекцию, gate/up считаются полностью — честно отметить в стоимости.
- M-L3: **словарные признаки** [24] — SAE требует SGD, поэтому только в дистилляционном треке
  (или пропускаем, если не успеваем).
- M-L4: **ASVD** [26] — SVD для W·S, S = diag(mean|x|^α) по калибровке, ранг по доле параметров;
  применяем к gate/up/down первых k слоёв (и отдельно к проекциям внимания для полноты).
- M-L5: **SVD-LLM** [27] — отбеливание по Холецкому от XXᵀ + усечение SVD (замкнутая форма).
  Их шаг «parameter update» (дообучение) — только в дистилляционном треке.
- M-L6: **Deja Vu** [28] — в детерминированном треке «оракульная» контекстная разреженность
  (истинные top-k нейронов на токене; совпадает с M-L2, это верхняя граница метода);
  обучаемый предиктор — в дистилляционном треке.
- M-L7: **MoEfication** [29] — разбиение нейронов на экспертов сбалансированным k-means по
  параметрам (детерминированная инициализация), маршрутизация без обучения — по близости
  входа к центроидам экспертов; доля экспертов ∈ {10, 25, 50%}.
- 2026-11-06: пользователь подтвердил добавление [26]–[29] в литературу и сравнение
  (literature.md, references.tex, раздел «Сжатие и разреженность MLP» в обзоре).

Наши:
- M-O1: **ridge-линеаризация MLP** — MLP(x̂) ≈ W x̂ + b, W из ridge-регрессии на калибровке
  (с PCA, как в O2); вариант «линейная часть + r точных нейронов» (остаток после A3-отбора
  компенсируется линейной картой, решение в замкнутой форме).
- M-O2: **табулированный MLP по токену** — для первых слоёв вход MLP ≈ функция текущего
  токена (+ поправка): T[x_t] = E[MLP(x̂_t) | x_t] по калибровке, плюс ridge-поправка
  по отклонению x̂_t от среднего для токена. Особенно для слоя 0 (MLP0 ≈ «расширенный эмбеддинг»).
- M-O3: **кусочно-линейная замена по кластерам** — k-means (детерминированная инициализация
  k-means++ с фиксированным seed) по x̂, в каждом кластере своя ridge-линейная карта.
- Комбинации для блока целиком: лучший метод внимания (L1/O4) + лучший метод MLP; сравнить
  с O3 (n-граммная таблица блоков).

Метрики те же (KL, PPL, top-1, бенчи) + доля сэкономленных FLOPs/параметров MLP первых k слоёв.

## 2026-11-07 22:40: механизм обрыва на k=3 найден — отравление калибровки массивной активацией

Диагностика (results/0.6b/cliff/analysis.json), M-O4 k=3:
- ошибка остаточного потока по входам слоёв: 0.18 (сл.1) → 0.19 (сл.2) → **0.54 (сл.3)**: скачок происходит
  ВНУТРИ заменённого слоя 2 (усиление 2.8), а не в слое 3; слой 3 (оригинальный) ошибку не усиливает (0.86).
- 85% энергии ошибки на входе слоя 3 — в 8 каналах массивной активации [35,13,1,277,7,23,3,8]
  (у сигнала учителя там 31%; у окна 3.6%, у SVD-LLM 1.7%). Масса стока в слое 3 падает 0.63 → 0.50.
- Причина: в калибровке (131k токенов, окна по 512 без BOS) ровно один токен («8» на позиции 1 одного окна)
  даёт выход MLP слоя 2 с нормой 7059 при медиане 4.9 — это 98.2% энергии целей наименьших квадратов слоя 2.
  Линейная поправка W и предиктор A подгоняются под эту строку → ошибка в массивных каналах у всех токенов.
  Слои 0–1 не затронуты (массивная активация создаётся MLP слоя 2), при k=4 поправка слоя 3 частично компенсирует.
- Корректоры на входе слоя 3 (diag/full/lowrank/massive8), подогнанные на сырых остатках, УХУДШАЮТ (27→35–45%):
  та же причина — строка с нормой 7059 доминирует и в регрессорах. Вывод: нужна робастная калибровка.
Исправление: detlayers/mlp.py: robust_pairs(gen, tau) — строки с ||y|| > tau·медиана (tau=10) обнуляются;
параметр robust_tau у build_ours_mlp/build_mlp. Новые конфигурации (старые оставлены как «наивная калибровка»):
MO4-routed25r, B-window+MO4-25r (+howmany: B-window64+routed25r), MO1-ridge-keep25r; этап `robust` в sweep.py,
в порядке `all` после final. Запущен отдельно: logs/sweep_mac_robust.log (0.6B; 1.7B догонит сторож).
Для статьи: раздел «Распространение ошибки и робастная калибровка»; проверить A3 (отбор по Σz²) и salience —
они тоже накапливают суммы по токенам без защиты от выбросов.
